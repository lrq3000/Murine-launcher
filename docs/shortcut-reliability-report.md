## Integrated behavior

- `ShortcutAvailabilityJournal` centralizes ordinary application decisions using stable profile serial/package history and exact workspace-generation/item/component keys. Unknown, external and recovering targets remain in favorites and the model; unrelated activity resolution, another mounted volume, boot completion and elapsed time cannot reactivate or remove them. Exact enabled component resolution is required for recovery. Current-process known internal targets retain legacy behavior outside recovery; historical internal classification alone is provisional after restart for fail-safe reasons described in the ledger.
- `AtomicAvailabilityPersistence` stores a versioned, CRC-checked journal with AtomicFile and explicit fsync. It lives in noBackupFilesDir so device-specific storage associations and old events are not restored to another device. Missing/corrupt/unreadable metadata and failed writes disable destructive journal authority. Ordinary loader observations are batched; uninstall/unavailable/add receipt and insertion fences are immediately durable.
- `WorkspaceDatabaseIdentity`, `DatabaseHelper` and `ModelDbController` add an idempotent identity table without changing favorites columns or SQLite user_version. Existing favorites are not recreated for this addition. Explicit existing empty-workspace resets also reset the identity. New ordinary rows receive a write-ahead generation fence before database insertion, preventing an earlier uninstall from deleting reinstall rows. Failed unsafe fences defer that insertion instead of risking deletion.
- `ModelInitializer`, `ModelLauncherCallbacks`, `LauncherModel` and `PackageUpdatedTask` retain authoritative removal origin. Callback receipt is journaled off-UI on the existing helper executor, including while the model executor is loading; model/database work remains serialized on MODEL_EXECUTOR. Pending removals become exact-row tombstones before the unloaded-task discard gate and before final workspace binding. Reconciliation is idempotent across interruption, scopes profiles/components/database generations, and also protects known inactive layouts against stale reinstalls.
- `WorkspaceItemProcessor`, `LoaderCursor`, `LoaderTask`, the legacy `SdCardAvailableReceiver` and package-update deletion predicates apply the same availability policy. Protected rows retain their original intent, placement and identity and occupy their normal workspace/dock/folder positions. Existing corrupt-intent, removed-profile, restore/archive, deep-shortcut, widget and placement-validation paths remain specialized. Folder rank compaction is suspended while an ordinary child is unavailable.
- `LoaderCursor`, bulk icon loading, `WorkspaceAvailability.cacheAppearance`, `CacheDataUpdatedTask` and `WorkspaceItemInfo.onAddToDatabase` preserve valid cached labels/images and avoid generic/empty failed-query writes. Normal full-resolution folder images are cached using a copy rather than promoting every in-memory child. Existing Murine custom-label/icon storage is not replaced or cleared. Only NOT_AVAILABLE is cleared on recovery; other disabled bits survive.
- `Launcher`/`LauncherModel` revalidate on foreground entry and coalesce foreground-only retries while unavailable targets remain. Pause/destroy cancels retries. Lifecycle-owned boot/media receivers only accelerate revalidation and are unregistered on teardown. Tapping an unavailable item uses existing localized unavailability feedback and requests a recheck. `ItemInstallQueue` suppresses automatic additions when the same profile/package already occupies the workspace.
- Storage observation uses ApplicationInfo.storageUuid, FLAG_EXTERNAL_STORAGE, StorageManager.getStorageVolumes, StorageVolume.getUuid and getState. Only an exact publicly exposed UUID match establishes a mapping; adopted/private/public mismatches remain unknown. A mounted volume does not establish package/activity registration. No new API30 storage callback or API31 getStorageUuid call is used.

## Remaining risks and acceptance limits

- Publication is blocked on full Java/Kotlin/Dagger/application compilation, the three real Android persistence tests, the canonical model regression and broader platform tests. Forty-two host assertions do not prove database/model/UI integration. Real `_id`, cells, screen, folder ranks, intent, label/icon/customizations and rendered unavailable appearance must still be compared before/during/after storage loss on a supported test target.
- Callback receipt versus final bind is linearized under the adapter lock; actual UI delivery, rapid replacement races, profile locking/administration, foreground retry lifecycle and process-kill timing require runtime validation. Author self-review is not a substitute for the coordinator's independent review.
- An authoritative uninstall missed while the process was stopped cannot reliably be distinguished from unavailable storage using negative lookups. External/unknown/recovering targets remain preserved. The conservative current-process internal-proof rule can also retain a missed internal uninstall after restart. Explicit user removal remains available; no timeout is allowed to resolve that ambiguity by deletion.
- The current active workspace and previously journaled workspace generations are covered by uninstall snapshots/tombstones. A never-loaded inactive database with no journal entries is not proactively opened/scanned; restoring or activating such a layout later is an additional unverified reconciliation case.
- A failed write-ahead fence can defer a new shortcut insertion. That is intentionally safer than allowing an old tombstone to delete a new installation's row, but the existing ModelWriter/UI treatment of the failed insertion still needs testing.
- Physical Lenovo P11 / Android10 behavior, adopted-storage mappings on that firmware, an effective minSdk APK inspection and independent downstream installation have not been validated. No claim of a functioning APK is made.
